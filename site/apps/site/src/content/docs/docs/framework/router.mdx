The mx router is a single Traefik container per workstation. Every mx project
attaches to the same Docker network and declares a `Host()` rule in its compose
labels; Traefik reads those labels off the Docker socket and routes by hostname.
Application services publish no HTTP host port at all, so two ecosystems can both
run a web app on container port 3000 and never collide.

## Install once, per machine

```bash
mx router install    # copies the Traefik config to ~/.mech-crate/router, creates devmesh-traefik
mx router up         # start (or re-apply config to) the router
mx router status     # installed / running / network / dashboard URL
```

`mx router status` prints something like:

```
Router Status
────────────────────────────────────────
  Installed: installed
  Status: running
  Network: devmesh-traefik
  Dashboard: http://localhost:7680
  Location: /Users/you/.mech-crate/router
```

The rest of the verbs: `down`, `restart`, `logs`, `inspect`, `network`,
`uninstall`. Aliases exist for most (`start`/`up`, `stop`/`down`, `ps`/`status`,
`info`/`inspect`, `remove`/`uninstall`).

## Connecting a service

`mx add --domain <host>` writes these labels for you. This is what they look
like, and what you would write by hand for a service mx did not scaffold:

```yaml
services:
  myapp:
    networks:
      - default              # internal: db, redis, siblings
      - devmesh-traefik      # external: how Traefik reaches you
    labels:
      - traefik.enable=true
      - traefik.http.routers.myapp.rule=Host(`myapp.localhost`)
      - traefik.http.routers.myapp.entrypoints=web
      - traefik.http.services.myapp.loadbalancer.server.port=3000
      - traefik.docker.network=devmesh-traefik

networks:
  devmesh-traefik:
    external: true
```

Three things matter and are easy to get wrong:

1. **Both networks.** `devmesh-traefik` is how the router reaches the container;
   `default` is how the container reaches its database. Only the service that
   receives external traffic needs the first one — Postgres, Redis and workers
   stay on `default` only.
2. **`traefik.docker.network`.** A container on two networks has two addresses.
   Without this label Traefik may pick the wrong one and you get a 502.
3. **`loadbalancer.server.port` is the *container's* port**, not a host port.
   There is no host port.

The routing rule is a Traefik matcher, so the usual composition works:
`Host(...) || Host(...)`, `Host(...) && PathPrefix(...)`, `HostRegexp(...)`.

## Two ecosystems at once

This is the point of the whole arrangement. Project A's `api.localhost` and
project B's `admin.localhost` are two containers on one shared network behind one
Traefik. Switching between them is `cd` — no teardown, no port bookkeeping, no
lost container state. Start the subset you need:

```bash
make dev s=api        # in project A
make dev s=admin      # in project B — both reachable, simultaneously
```

Dev overrides *do* publish conventional host ports for backing services (Postgres
on 5432, Redis on 6379) so local GUI tools can reach them. That is per compose
file and easy to change if you genuinely need two databases up at once.

## Tuning

| Variable | Default | Effect |
|---|---|---|
| `MX_ROUTER_HOME` | `~/.mech-crate/router` | State directory |
| `MX_ROUTER_NETWORK` | `devmesh-traefik` | Docker network name |
| `MX_ROUTER_DASHBOARD_PORT` | auto | Pin the dashboard port |
| `MX_ROUTER_DASHBOARD_RANGE` | `7680-7799` | Range the dashboard is allocated from |

## When a hostname does not answer

Work down this list; it is ordered by how often each one is the cause.

1. `mx router status` — is the router even running?
2. `docker ps` — is the service running, and is it healthy?
3. Is the service on `devmesh-traefik`? A container that is not on the network is
   invisible to Traefik no matter how good its labels are.
4. Open the dashboard (`mx router status` prints the URL) and look at Routers.
   A missing router means the labels did not parse; a router with no service
   behind it usually means `traefik.docker.network` is wrong or absent.
5. A 502 rather than a 404 means Traefik found the container and could not reach
   the port — check `loadbalancer.server.port` against what the app binds.

`mx router restart`.
